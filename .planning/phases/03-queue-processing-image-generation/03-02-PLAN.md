<task type="auto">
  <name>Task 2: Create kie.ai API client with retry logic</name>
  <files>lib/queue/kie-api-client.ts</files>
  <action>
Create kie.ai API client wrapper with p-retry for resilience:

1. Define KieAIPayload interface:
   - model: 'nano-banana-pro'
   - input.prompt: string
   - input.image_input: string[] (URLs, max 8)
   - input.aspect_ratio: string
   - input.resolution: string
   - input.output_format: 'PNG' | 'JPG'

2. Define KieAITaskResponse interface for API responses

3. createKieAITask function:
   - Accepts KieAIPayload
   - POSTs to https://api.kie.ai/api/v1/jobs/createTask
   - Uses Authorization: Bearer ${KIE_API_KEY}
   - Wraps in pRetry with:
     - retries: 5
     - factor: 2 (1s, 2s, 4s, 8s, 16s)
     - minTimeout: 1000
     - maxTimeout: 30000
     - randomize: true (jitter to prevent thundering herd)
   - Throws AbortError for non-retryable: 401, 402, 422
   - Retries on: 429, 500, 502, 503, 504
   - Returns taskId on success

4. pollTaskCompletion function:
   - Takes taskId string
   - GETs https://api.kie.ai/api/v1/jobs/queryTask?taskId=${taskId}
   - Wraps in pRetry with:
     - retries: 60 (poll for up to ~5 minutes)
     - factor: 1.2 (slower growth for polling)
     - minTimeout: 2000 (start at 2s)
     - maxTimeout: 10000 (cap at 10s)
     - randomize: true
   - If status is 'queued' or 'processing': throw Error (triggers retry)
   - If status is 'failed': throw AbortError (no retry)
   - If status is 'completed': return { resultUrl: data.data.result_url }

5. Export getKieApiKey helper that validates KIE_API_KEY env var exists

Use AbortError from p-retry for non-retryable errors.
Log retry attempts with onFailedAttempt callback.
  </action>
  <verify>TypeScript compiles: `npx tsc --noEmit lib/queue/kie-api-client.ts`</verify>
  <done>kie.ai API client exports createKieAITask and pollTaskCompletion with proper retry logic</done>
</task>

<task type="auto">
  <name>Task 3: Create generation queue manager</name>
  <files>lib/queue/generation-queue.ts</files>
  <action>
Create GenerationQueueManager class using p-queue:

1. Import PQueue from 'p-queue'
2. Import createKieAITask, pollTaskCompletion from './kie-api-client'
3. Import GenerationJob, GenerationState from '@/lib/types/generation'
4. Import createServerSupabaseClient from '@/lib/supabase-server'

5. GenerationQueueManager class:
   - Private queue: PQueue with concurrency: 20, autoStart: true
   - Private supabase client (created via createServerSupabaseClient)
   - Private kieApiKey: string (passed to constructor or from env)

   Constructor:
   - Initialize PQueue with concurrency: 20
   - Set up event listeners:
     - 'active': log queue status (pending, running)
     - 'idle': log "all jobs complete"
     - 'error': log errors

   addGeneration(job: GenerationJob): Promise<GenerationResult>
   - Add to queue via queue.add()
   - Inside queue callback:
     a. Update DB state to 'processing' with explicit record identification:
        ```typescript
        await supabase
          .from('generations')
          .update({ state: 'processing', started_at: new Date().toISOString() })
          .eq('id', job.id)  // WHERE id = job.id
        ```
     b. Call createKieAITask with job details
     c. Update DB with task_id using explicit record identification:
        ```typescript
        await supabase
          .from('generations')
          .update({ task_id: taskId })
          .eq('id', job.id)  // WHERE id = job.id
        ```
     d. Call pollTaskCompletion(taskId)
     e. Update DB state to 'completed' with explicit record identification:
        ```typescript
        await supabase
          .from('generations')
          .update({
            state: 'completed',
            result_url: resultUrl,
            completed_at: new Date().toISOString()
          })
          .eq('id', job.id)  // WHERE id = job.id
        ```
     f. On error: Update DB state to 'failed' with explicit record identification:
        ```typescript
        await supabase
          .from('generations')
          .update({
            state: 'failed',
            error_message: error.message,
            completed_at: new Date().toISOString()
          })
          .eq('id', job.id)  // WHERE id = job.id
        ```
   - Return GenerationResult with state and resultUrl

   addBatch(jobs: GenerationJob[]): Promise<GenerationResult[]>
   - Map jobs to addGeneration promises (DO NOT await individually - this kills concurrency!)
   - Return Promise.all of all promises

   getStatus(): { pending: number, queued: number, total: number }
   - Return queue.pending, queue.size, sum

   waitForCompletion(): Promise<void>
   - Return queue.onIdle()

   pause(): void - queue.pause()
   resume(): void - queue.start()
   clear(): void - queue.clear()

6. Export singleton instance pattern:
   - let instance: GenerationQueueManager | null = null
   - getQueueManager(): GenerationQueueManager
   - Returns existing instance or creates new one

CRITICAL: Do NOT await queue.add() calls serially in a loop - this defeats concurrency.
Map all jobs first, then await Promise.all or queue.onIdle().

CRITICAL: All database updates MUST use .eq('id', job.id) to identify the specific generation record.
  </action>
