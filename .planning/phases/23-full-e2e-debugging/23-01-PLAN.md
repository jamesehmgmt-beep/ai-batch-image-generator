<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Manual upload flow testing</name>
  <what-built>Upload flow for folder drag-and-drop with structure preservation</what-built>
  <how-to-verify>
Test the following scenarios at http://localhost:3000:

**Test 1: Single folder upload**
1. Create a test folder with 3-5 images (e.g., TestFolder with image1.jpg, image2.png, image3.jpg)
2. Drag and drop the folder onto the dropzone
3. Verify:
   - [ ] Folder tree shows the folder name
   - [ ] File count displays correctly (e.g., "3 files")
   - [ ] Progress indicator completes
   - [ ] No console errors in browser DevTools

**Test 2: Multiple nested folders**
1. Create a folder structure:
   ```
   ParentFolder/
     ChildA/ (2 images)
     ChildB/ (3 images)
   ```
2. Drag and drop ParentFolder
3. Verify:
   - [ ] Both ChildA and ChildB appear in tree view
   - [ ] File counts are accurate for each folder
   - [ ] Folder hierarchy is preserved

**Test 3: Mixed file types (edge case)**
1. Create folder with mixed files (images + non-images like .txt, .pdf)
2. Drag and drop
3. Verify:
   - [ ] Only images are counted
   - [ ] Non-image files are ignored without error

**Test 4: State persistence**
1. After successful upload, click "Create Generation Job" button
2. Verify navigation to /create-job
3. Check browser sessionStorage for `bulkImageGen_jobSession` key
4. Verify:
   - [ ] Session data contains uploadSessionId
   - [ ] Session data contains dropResult with folder tree
   - [ ] fileCountByFolder has correct counts

**Test 5: Page refresh resilience**
1. On /create-job page, refresh the page (F5)
2. Verify:
   - [ ] State is restored from sessionStorage
   - [ ] Folder information still visible
   - [ ] No "missing data" errors

Document any issues found with:
- Steps to reproduce
- Expected behavior
- Actual behavior
- Browser console errors (if any)
