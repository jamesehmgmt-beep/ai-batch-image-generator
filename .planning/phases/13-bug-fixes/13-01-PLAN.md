Output: Modified job creation API that returns error response when generation inserts fail.

  <name>Task 1: Propagate generation insert errors to client</name>
  <files>app/api/job/create/route.ts</files>
  <action>
Modify the generation insert error handling at lines 220-223. Currently the code says:
```typescript
if (genError) {
  console.error('[Job Create] Error creating generations:', genError);
  // Don't fail the job creation, just log the error
}
```

Replace with error propagation that returns a 500 response:
```typescript
if (genError) {
  console.error('[Job Create] Error creating generations:', genError);
  return NextResponse.json(
    {
      success: false,
      error: `Failed to create generation records: ${genError.message}`,
      jobId: job.id,
      details: {
        attempted: actualGenerationCount,
        errorCode: genError.code
      }
    },
    { status: 500 }
  );
}
```

Keep the console.error for server-side debugging but now ALSO return the error to the client so they know the job creation failed.

Include the job.id in the response so users/developers can debug what happened to that specific job.

```typescript
if (actualGenerationCount === 0) {

  console.error('[Job Create] filesByFolder keys:', Object.keys(filesByFolder));

    {
      success: false,
      error: 'No generations could be created. Folder paths in your prompt may not match uploaded folders.',
      jobId: job.id,

        uploadedFolders: Object.keys(filesByFolder)
      }

    { status: 400 }
  );
}
```
